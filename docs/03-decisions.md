# Decisions

Each decision has a status, the reason, and when to revisit. Many of the *Rejected* items came from early agent pushback in 2025, so they are here to be questioned, not obeyed.

Statuses: **Accepted**, **Rejected**, **Reopened** (under discussion), **Parked** (later), **Superseded**.

## Technical

| D-01 | Rebuild in Rust, replacing Electron + React + TypeScript | Accepted | Speed and a safe core. The old stack had unmaintained parts (Create React App, mmap-io, fluent-ffmpeg) and constant native-rebuild trouble. |
| D-02 | Memory-map **local** files only | Accepted | Mapping network files can crash on disconnect and is slow. Compressed files are decoded straight from the network in one pass. Uncompressed files on a network drive are copied to local temp first, then mapped. See the table in 03-architecture. |
| D-03 | Decode once, work from memory, cache measurements | Accepted, with a caveat | The old "mmap for preview" never fed FFmpeg, so it did not help. That is about 1.6x faster, not the dramatic win first expected, because FFmpeg also seeks and does not re-decode the whole file per track. The bigger saving should come in the full run, where analysis and export share one decode. Reading the file alone takes 2.4 s of the 5.7 s. |
| D-04 | The "Range" column shows LRA (loudness range) | Accepted | Decided 2026-10-23. | D-11 | The cache recognises a file by content, not name or date | Accepted | Key is the file size plus a hash of three 64 KiB slices. It survives renames, copies and moves, which the app's own File Strategy and the NAS both cause. Cost: three small reads per file. Known trade-off: editing the tags changes the first slice, so a re-tagged file is measured again. Results are stored per CUE layout (in CD frames, so independent of sample rate), and a version number discards old entries when the measuring code changes. Measured on Houses of the Holy: 5.3 s cold, 0.00 s cached. |
| D-12 | Gain only. The true-peak ceiling is the hard limit on how far the volume knob can turn. | Accepted | Decided 2026-10-24. The tool never compresses or limits the waveform, so no peak data is ever lost. The ceiling decides how much gain a song can take, and a song that runs out of headroom stays below the target and is marked `*`. Seen on Houses of the Holy at -16 LUFS with a -0.6 dBTP ceiling: The Rain Song wants +4.66 dB but can only take +1.31 dB. Someone who asks for -10 LUFS with a 0 dBTP ceiling will get a wide spread of volumes, and that is the setting working as intended, not a flaw. Any waveform compression is an optional extra for much later, after everything else works. For that day: a light limiter measured on this album reached the target within 0.1 LU and moved the loudness range by under 0.2 LU, but FFmpeg's `alimiter` works on sample peaks, so it needed to be set about 1.4 dB below the true-peak ceiling to stay under it. A listening comparison is in `testdata/ab-limiter/`. **Clarified 2026-11-09:** this rule is about dynamics. Format conversions (resampling, bit depth, mixing channels) are allowed and are not compression (D-35), and an opt-in limiter is the only way compression could ever arrive (D-36). Neither changes the default. |
| D-13 | Nothing original is touched until everything has been written | Accepted | Every song is encoded to a temporary file, and files are only moved into place once the whole source has decoded and every encode has succeeded. A failure deletes the temporary files and leaves originals as they were. Tested, including a failed placement. |
| D-14 | File Strategy meanings | Accepted, reshaped by D-21 (the four choices below are now three separate ones; numbering only happens on a clash) | Serialize always adds the suffix. Rename-old renames an existing file at the same path and never overwrites an earlier backup. Replace overwrites only a file at exactly the same path and never deletes a differently named source. Save-to writes elsewhere and serializes clashes. Replace needs an explicit `--yes` on the command line. For a CUE album, which has no same-named output to replace, Replace writes the songs next to the image and keeps the image (decided 2026-10-24). Replace is expected to become the default strategy once it has proven itself, and until then the safer choices stay the default. Planned: after a run that has been verified, offer to move the CUE image (or a replaced source) to the Recycle Bin or Trash, always with explicit confirmation. Rule for testing it: the real action sits behind a small interface with a fake for tests, and tests only ever use generated files or copies in temporary folders, never `testdata/` originals or the real Recycle Bin. |
| D-15 | Dither only when needed | Accepted | A gain on 16-bit audio, or a drop from 24 to 16 bits, uses triangular dither. Since 2026-11-09 the rule also dithers a 16-bit result whenever the signal was converted (a mix of the channels, or a new sample rate), even at 0 dB, since those make every sample a new value (D-35, D-37). |
| D-16 | FFmpeg is found via `RANGEFORGE_FFMPEG`, next to the program, on the path, or in the usual package folders | Accepted for now | A window opened from Finder or the Start menu does not get a terminal's path, so on a Mac the Homebrew folder (`/opt/homebrew/bin`) would be missed. | D-17 | Peaks above 0 dBFS, and hitting a LUFS target without losing peak data | Parked, to discuss together with any compression | Raised 2026-10-24: the user has seen digital peaks over 0 in a real file, and other people's files and habits will be messier than their own. When compression comes up, the same conversation must cover ways to reach a loudness target while preserving peaks, and what to do with "overs". Three different cases: inter-sample overs (all stored samples at or below 0 dBFS, but the waveform between them goes higher, which true peak measures), float files (can store samples above 0 dBFS), and already-clipped files (flat tops, so the data is gone). Today the planner already handles the first two without losing data, because a file whose true peak is above the ceiling gets a negative gain until it fits, and the decoder keeps values above 1.0. Gaps to close: a float output option (32-bit float WAV is the only common container that can hold overs, ALAC and FLAC cannot), a warning when peak protection is off and a gain would clip on the way out, and a tool-side flag for files that arrive already clipped. Tests to add then: a float WAV with samples above 1.0 measured and exported. See D-36 for the opt-in limiter, which does not replace the float-output and clipped-file items here. |

| D-35 | Format conversions (resampling, bit depth, channel mix) are allowed; the one gain comes after them and is measured on what is written | Accepted; built 2026-11-09 | Decided 2026-11-09. D-12 is a rule against dynamics processing (compression, limiting), not against conversion: resampling (D-27), a drop in bit depth (D-15) and mixing channels all change samples by necessity and are not volume work. The order is **convert, then measure, then apply one gain, then encode**. **Why measure after:** mixing 6 channels down to 2 changes the loudness and raises the peaks, because channels are summed, so the loudness and the true peak that the gain and the ceiling work from must be those of the converted sound. Resampling can create inter-sample peaks, so the ceiling is checked after it too. **What "measure once" becomes:** with every conversion set to original, the saved measurement is used as it is. A conversion that changes the signal (a channel mix) is measured on the converted audio and saved under its own key, so one album measured for stereo and for 5.1 keeps two entries (D-11's key gains the mix choice). **Channels (settled 2026-11-09):** Original, Quad, Stereo, Mono. A mix only ever reduces channels: asking for as many channels as the file has, or more, means original, and nothing is upmixed. **Files with more than 6 channels (7.1, 9.1, 11.1) are always written as they are**: they are leveled for volume, not downmixed, because the people who work with them have matrix processors that already do the downmix, and with tools for it; the use is bulk volume leveling of large movie assets that will not be downmixed anyway. Left-only and right-only are not offered. **The recipe is the hard part.** Like turning a colour photo into black and white, there is more than one honest way, so the Channels choice comes with a **Downmix** style, shown only when Channels is not Original (it is called Downmix, not "downsample", which already means the sample rate). Three styles (settled 2026-11-09): **Standard** (the default; the ITU-style downmix, centre and surrounds at -3 dB into left and right, the LFE dropped), **Standard + bass** (the same with the LFE added at -3 dB), and **Front pair only** (left and right as mixed; the centre and surrounds are discarded). Quad keeps front left, front right, back left and back right, with the centre folded into the fronts at -3 dB and the LFE dropped. Mono is the average of the standard stereo mix. The result is kept under the true-peak ceiling by the one gain, and the table shows the downmixed measurement. **Rejected until someone demands it:** a **centre boost** (it makes the result sound very different and "lossy" in a way that is not subtle compared with the accepted strategies, and it is inconsistent from file to file because of how channels relate in a multichannel mix; the user has seen the same in HandBrake), and Dolby-style matrix encodings. **Open:** how a quad source is mapped down to stereo or mono, and the exact scaling of the mono sum. The choices (Channels and Downmix) are saved in presets with the rest of the output format (D-18). **Checked:** the resampler and the dither, see D-37. **Measured 2026-11-09 on real 5.1 music** (Pink Floyd's *Dark Side of the Moon* and *Wish You Were Here*, 24-bit/96 kHz FLAC, and I Robot, DSD64), two minutes of each: the standard ITU stereo downmix (centre and surrounds at -3 dB, LFE dropped) came out between -0.6 and +1.6 LU of the 6-channel loudness, and its true peak was 2.6 to 4.9 dB above the 6-channel peak, so neither can be taken from the 6-channel measurement. Taking only the front pair lost 1.3 to 4.7 LU (the centre and surround content). Adding the LFE at -3 dB changed little (0 to +0.5 LU, up to +0.7 dB of peak). Resampling, in the same tests, added no measurable peak (D-37). **Built 2026-11-09, and what building it found.** (1) **Where:** the mix is applied to each decoded block (`for_each_block_mixed`), so the meter and the encoder both see the mixed sound and the gain comes after it; the measurement is keyed by the mix (`|mix=stereo-standard`, and nothing added when nothing is mixed, so older saved measurements still count), and changing Channels or the Downmix style measures the loaded files again, throwing away any answer that arrives for a mix that is no longer chosen. (2) **Channel order:** the decoders do not report a layout, so 6 channels are taken as front left, front right, centre, LFE, back left, back right, and 4 as quad. On the real 24-bit/96 kHz FLAC the program's decode is bit-identical to FFmpeg's on all six channels, and the stereo (all three styles), quad and mono mixes equal FFmpeg's own `pan` mix to within 1e-5. (3) **Mixes go over full scale:** the standard stereo mix of *Speak To Me* peaks at +0.78 dBTP where loud channels add up. FFmpeg's `pan` clips such a mix at 1.0; the program keeps the values until the one gain brings them down, which is the reason to measure the mix and not clip it. (4) **Quad and ALAC:** FFmpeg takes four channels for 4.0 (a centre and a back centre) unless told the layout, so quad is named `quad` to it; FLAC, WAV, AAC and MKA carry that correctly, but ALAC turns it into five channels with a silent centre, so Quad is refused with ALAC, in the window, the saved settings, presets and the command line. (5) **Dither** now also follows a converted signal, a mix or a new rate, at 0 dB on a 16-bit file (the gap in D-37). Checked on real files: a real 5.1 FLAC and a real six-channel DSD, leveled after the mix, land on the loudness they were planned to, under the ceiling. |
| D-36 | Peak-preserving loudness (limiting) may come, but only as an opt-in; gain-only stays the default | Accepted in principle; not built | Decided 2026-11-09, after the objection to waveform-changing normalization came up again. It is a fair objection for a tool whose point is leaving the music alone, and D-12 stands: by default one gain per song, and a song that runs out of headroom stays below the target and is marked `*`. For people and files that want the target reached anyway, an optional switch, **off by default**, would let a transparent look-ahead limiter act **only on songs that peak protection would otherwise hold back**, and only as much as is needed, up to a cap in dB. Songs that reach the target by gain alone are untouched, and a song written at 0 dB stays bit-exact. Every song that was limited says so, with the most reduction it was given, in the table and the log: it is never silent. The test in D-12 gives the starting point: a light limiter reached the target within 0.1 LU and moved the loudness range by under 0.2 LU, but a sample-peak limiter had to sit about 1.4 dB under the true-peak ceiling to stay under it, so this one should work on true peak. **Open:** the cap, the look-ahead time, the ceiling it limits to, and whether the switch lives in Volume Adjustment or in a preset. Peaks above 0 dBFS (float output, clipped sources) stay in D-17. |
| D-37 | Resampling quality: measured on real files; a SoX (soxr) upgrade is proposed, not made | Measured; open | Measured 2026-11-09 with FFmpeg's `aresample`, which the app uses for the final rate change (a long filter, `filter_size=64:phase_shift=14:cutoff=0.97`), on generated tones and on real files: *Dark Side of the Moon* (24-bit/96 kHz, 6 channels, front pair, three tracks) to 44.1 kHz, and I Robot (DSD64) through the app's first conversion to 88.2 kHz. **What is already good:** on real music the audible band (0 to 20 kHz) differs from a very-high-precision reference by -98 to -105 dB relative to the music, which is the 16-bit noise floor and inaudible. The true peak after resampling is unchanged (for example -9.2 dBTP in and out on all three tracks), and through `rangeforge run` at a -10 LUFS target (peak protection the limit) the written files sit at -0.6 to -0.5 dBTP with or without a rate change (the two meters differ by 0.1 dB at 44.1 kHz even with no resampling). Loudness lands on -22.00 LUFS at every rate tried (44.1, 48, 96, and DSD to 44.1 or 88.2). **What a SoX resampler would add** (`aresample=resampler=soxr:precision=28:cutoff=0.97`; the bundled Windows FFmpeg has libsoxr): a much steeper edge. A tone just above Nyquist (22.5 kHz) is cut by only 29 dB now and by about 165 dB with SoX; a 25 kHz tone by 107 dB against 150 to 165 dB; a 21 kHz tone is down 2.8 dB now and flat with SoX. On real music the audible-band difference from the reference goes from -98 or -105 dB to -123 or -134 dB, and the first DSD conversion is about three times faster (0.6 s against 1.8 s for 30 s of six channels). FFmpeg's own defaults are worse than the current settings (about -70 dB on music), so the current choice was a good one. Speed for a whole track is the same (about 1 s for 212 s of six channels). **Why it is open, not done:** the gain on music is small and below what anyone can hear; it needs a check at run time that the FFmpeg in use has libsoxr (the Mac and Linux builds are made by `scripts/fetch-ffmpeg.sh`, which would need it added), with the current settings as the fallback; and changing the DSD stage changes the saved measurements slightly, so their version would have to change. **Dither (D-15):** 24 to 16 bits is as it should be (a flat noise floor, no harmonic lines, where plain rounding leaves only harmonics). One gap: a 16-bit source resampled at exactly 0 dB gain is not dithered, because the rule looks at bit depth and gain only, and the error then shows as harmonic lines 42 to 54 dB above the floor (against about 12 dB with dither, at the cost of 2 to 7 dB more noise). It almost never happens, since gain is rarely exactly 0, and the fix is to dither whenever the rate changes. **Fixed 2026-11-09:** the 16-bit dither gap above is closed; a new sample rate or a channel mix now dithers a 16-bit result even at 0 dB. |
