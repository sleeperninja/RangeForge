# The screen

**In short:** the window is a list of your music on top and a strip of controls underneath. You drop files anywhere on the window. The list fills in with measurements. You adjust the settings. You press **Run**.

The pictures in [mockups/](mockups/) are the source of truth. This page explains them in words. If they ever disagree, the pictures win and this page gets fixed.

## What you see, top to bottom

1. **Title bar:** the app name and window buttons, in the app's own dark style.
2. **The list:** most of the window. Scrolls when it is full.
3. **The controls strip:** along the bottom. Details below.
4. **The log panel:** an optional column on the right. Shows what the app is doing, step by step.

## The list

Each row is a song or a file. A CUE album (one big file described by a `.cue` sheet) shows as a parent row with its songs indented underneath.

| Column | What it tells you |
| --- | --- |
| Name | The album or song. Songs sit under their album. |
| Codec | The audio format. See below. |
| Loudness | How loud the song is now (LUFS). |
| True Peak | The highest point the sound reaches (dBTP). Too high means distortion. |
| Adjust | How much louder or quieter the app will make this song to hit your target. |
| Range (LRA) | How much the loudness rises and falls within the song, in LU. A small number is steady, a big number is very dynamic. *The mockup's header still says "(DR)"; change it to "(LRA)" next time the mockup is edited.* |
| Tags | Genre labels. Colours explained below. |

A row still being measured shows `-` and fills in when ready.

**The Codec column**
- Album row: `Split(cue)` means "this will be cut into songs".
- A single file: the format it came in as, in brackets, like `(flac)`.
- A song row: the format it will be written as.
- *Open to a clearer design.* One idea is `flac → alac` on song rows, showing both sides together.

**Tag colours** (picked casually, easy to change)
- Plain: tags for the whole album, like Classic Rock.
- Blue: **Radio** (the default text). The song reached the Billboard Hot 100, at or above the threshold set in Settings (D-47).
- Pink: a tag that belongs to one song, like Funk Rock on an album that is otherwise Hard Rock.

**Where the tags come from, and what is written** (built; needs the Metadata API switch)
- The plain tags are the genre already in the file or CUE sheet first, then up to three genres Last.fm's listeners give the album. Last.fm's tags are filtered: opinions (awesome), habits (seen live, albums I own), places (british), decades (70s) and the artist's own name are dropped, and only tags with at least 5 hits count (Last.fm's popularity, 0 to 100; real genres like Dream Pop show up at 8, while list-style tags such as "albums you must hear before you die" and "best of 2000" sit at 1 or 2). The most-used usable one is always kept, so an album has a genre if there is any.
- **Song-level genres (added by you):** Last.fm's API gives no song tags, and its tags page sits behind a bot check, so the program cannot read it (D-31). Instead, right-click a song → **Open song tags page on Last.fm** opens it in your browser, and you add what you want from it with **Add a tag…** (see below). They are green tags, and like any hand-added tag they are kept for the session only. The pink song tags are meant for a song-level source and there is none right now.
- The pink tags are up to four that stand out for the song itself and are not already the album's. They are allowed to be rarer than the album's (a tag with 5 hits or more shows), because that is exactly what sets a song apart.
- Tags you add by hand are **green**.
- **Radio** is added last when the song charted. Settings has a **Hot 100 tag** section: a switch (on by default), the tag's text (default `Radio`, at most 30 characters; commas and semicolons become spaces, empty means the default) and a position 1 to 100 (default 100: the song's best chart position must be this or better). These are remembered between sessions.
- When you press Run, these are written to each file's **genre tag, comma separated, with Radio last**, for example `Classic Rock, Hard Rock, Funk Rock, Radio`. With the Metadata API switch off, genres are neither shown nor changed.
- Each lookup is written to the log with the exact names sent and the tags that came back, each with its score out of 100 (songs: a score made up from the tag's place on the page). For an album, "Last.fm has no tags for…" means the names did not match anything at Last.fm: fix them with **Album & track names…**. Songs are not asked of Last.fm (D-31).
- Each album and song is asked about once and the answer is remembered for 90 days (14 days when Last.fm had nothing), so a big collection is only slow the first time. **Settings → Clear saved Last.fm answers** forgets them all so genres are pulled fresh; the right-click **Get tags from Last.fm** items always ask afresh. Requests are spaced to stay within Last.fm's limits. If Last.fm cannot be reached or refuses the key, asking stops, the log says why, and it carries on the next time something triggers it.

**Who a song is** (artist, title, album): every lookup and every `{artist}`-style file name works from this, found in this order:
1. A CUE sheet's performer and title lines, for songs cut from an album.
2. The tags stored in the file, for single files. DSD files (`.dsf`, `.dff`) are read through FFmpeg, since the normal tag reader cannot open them.
3. A guess from the file's name and folders when there are no tags: `Artist - Title`, `07 - Title`, `07. Title`, `03 - Artist - Title`, and folders like `Artist/Album/`, `Artist - Album (1973) [FLAC]/` or `1973. Album/`. A bare `99 Luftballons` is kept whole, not read as track 99. Names made by a machine are read too: `00724352531929_001_Doves_Firesite_GBDGG0000013` is track 1, "Firesite", with the leading barcode (8 to 14 digits, followed by the track number) and the trailing ISRC (such as `GBDGG0000013`) dropped. Some stores keep the title's own spaces between the underscores (`00724387460928_001_Doves_Some Cities_GBDGG0400080`), which is read the same way. Such a name runs artist and title together, so the artist is taken from the folder (a note in brackets such as `(lossless downloads from vinyls)` is ignored) and removed from the front of the title. A name with spaces and no barcode or ISRC is the person's own and is never trimmed that way.
4. Typed in by hand (right-click **Album & track names…**). It replaces whatever was known, shows as "typed in by you" when the pointer rests on the song, and a later scan never overwrites it.

Resting the pointer on a song's name says who it is taken to be and which of these it came from, and calls a file-name guess a guess. A song with no artist and title cannot be looked up, and simply gets no Radio tag.

**Editing tags and names** (kept for the session; they are gone when the list is cleared or the program closes)
- Each tag chip has a small **×** that removes it from that song, Radio included. A removed tag stays removed when Last.fm is asked again. If every tag is removed, the genre tag is written empty rather than left as it was.
- Right-click → **Add a tag…** adds green tags. The box takes one tag or several, separated by commas, semicolons or line breaks, so a list copied from a web page, a spreadsheet or another program's tag field can be pasted as it is; a tag repeated in other letters is added once. On an album it adds to every song, and with several songs picked it adds to all of them.
- Right-click a song, an album or an album's heading → **Album & track names…** (D-33): one dialog for an album and its songs. It always covers the whole album the row belongs to (the files gathered under one heading, or a lone file by itself), whichever row it was opened from. At the top are **Artist**, **Album** and **Album artist**; a box left empty keeps what each song has. Below is one row per song, with its title in a box you can type in and the album's track list offered as suggestions. **Get track list** asks Last.fm (needs a key and the Metadata switch) using the names as typed in the boxes now, which need not be saved first, or lines up a list you paste (one title per line, a number or a time at either end being fine), and fills the rows as a first guess: by title first (the listed title found in the song's name, ignoring capitals and punctuation), then by track number, and if what is left over is equal in number, by order. Each row says how it was paired ("by track number only" and "by order only" are the weak ones, worth a look) and can be changed by typing. **Save** gives every song of the album the names in the boxes and gives the titles you changed theirs, all as names typed in by hand: a later scan never overwrites them, and the lookups use them. A title taken from the list also brings its place on the album, for a single file; one typed by hand does not. A song cut from a CUE sheet keeps the number and split points the rip gave it (D-34), and the names you type replace the sheet's in the written tags and the file names. A song's length is not used yet. Giving only some songs of an album a different artist (a compilation) is not possible yet.
- Right-click → **Get tags from Last.fm for this album** asks Last.fm now, even while automatic lookups are off (it needs a key and the main Metadata switch).
- Right-click → **Open song tags page on Last.fm** opens the song's tags page in your browser (with several songs picked, one tab each, at most 6). The page is built from the song's name as it stands, with plain punctuation and no version note, so **Album & track names…** fixes a wrong address.
- The edited names and tags are what the file names, the written tags and the Last.fm questions use.

**Picking songs.** Click a song to pick it, Ctrl-click to add or drop one, Shift-click for a range. Clicking an album's row picks all its songs. Right-click one of several picked songs and **Add a tag**, **Open song tags pages**, **Get tags from Last.fm for their albums** and **Include / Leave out** work on all of them. **Select every song with this album** picks every song in the list with the same album name.

**Album headings.** Single files that are scanned, identified and share an album, artist and folder gather under one heading, like a CUE album: "Artist – Album (N songs)". The folder is part of the match so a stereo and a six-channel (`6ch`) copy of the same album stay apart. The heading's checkbox, click and right-click act on every file under it, and its ▾ folds the songs away. The files are still separate items underneath, so file names and writing are unchanged (D-30).

## The controls strip, left to right

**Run area**
- **Run (9):** processes the files. The number is how many. It counts your selection, or everything if nothing is selected.
- **Metadata API** (moved into the Settings window, D-46): on means "look up tags online". It starts off, so nothing touches the network until you say so. The blue **Radio** tag works as soon as it is on, with no key. Last.fm genres also need a key and their own switch in Settings.
- **Show Logs:** a switch button (shows "on" or "off") that opens or closes the log panel. Settings and About use the same button style as Clear completed and Clear all.
- **Clear completed / Clear all** sit under the Run button and the status line (D-43). Clear completed removes the albums that have been written; Clear all empties the list. Both wait until measuring and writing have finished.
- Below a spacer that stretches with the window, the rest of this column hugs the bottom: **Show Logs**, then **Settings** and **About** side by side.
- **Settings:** opens the Settings window.
- **About:** a small window with the version, **Support on Ko-fi** (the donation page), **Read the manual** and **FAQ** (the rendered files on GitHub), **Downloads** (the releases page, where the manual PDF is attached) and **Third-party notices**. Every link is a fixed name the program maps to a fixed address (`browser::about_address`); the page cannot choose where the browser goes.

**Output Format**
What the new files will be: codec, container, sample rate, bit depth, bitrate, compression and channels. Each can say "source", meaning keep what the file has (the saved setting is still called `original`). A control that does nothing for the chosen combination stays where it is, shows no value and is dimmed, so the panel never jumps about (this is the rule for any option with nothing to see): **Bitrate** is dimmed for the lossless codecs, **Compression** for everything but FLAC, **Bit Depth** for the lossy ones, **Sample Rate** for Opus, and **Downmix** while Channels is Original.

**32-bit float** (D-41) is a Bit Depth choice that appears only for WAV. Whole-number files stop at full scale, so with Peak Protection off a gain that goes past 0 dB clips them; a float file keeps those peaks. It is never dithered. While it is selected, **Peak Protection** shows unticked and dimmed (and the ceiling box is empty), because a float file has no full scale to protect; the setting itself is not changed, so it comes back when another depth is chosen, and songs are planned with no ceiling. FLAC and ALAC cannot be written as float, and choosing another codec while it is selected puts the depth back to source.

**Codecs** (D-38): ALAC, FLAC, WAV, AAC, MP3 and Opus. **Bitrate** is for the three lossy ones. AAC offers 128, 160, 192, 256 (the usual) and 320 kbps. MP3 offers, from smallest to best, 128, 160, V4 (about 165), V3 (about 175), V2 (about 190), 192, V1 (about 225), 256, 320 (the usual) and V0 (about 245), where V0 to V4 are LAME's variable-rate settings; nothing below 128 and no V5 or lower. Opus offers 96, 128, 160, 192 (the usual), 256 and 320 kbps, and is variable-rate already, so these are the rates it aims for. **Compression** is FLAC's level, 0 (largest file) to 8 (smallest), 5 to begin with; the sound is the same at every level. **Sample Rate** for Opus shows 48 kHz and cannot be changed, because that is the only rate it is written at; MP3 stops at 48 kHz and AAC at 96 kHz, and a source above that (a 96 kHz file written as MP3) is brought down to the nearest rate in its family, 48 or 44.1 kHz. MP3 holds two channels, so a file with more needs Channels set to Stereo or Mono (it says so, and nothing is written), and Quad is not offered for it (as for ALAC). MP3 carries ID3 tags (version 2.3), Opus carries Vorbis-style tags. **Channels** (built, D-35) is Original, Quad (4.0), Stereo (2.0) or Mono (1.0). A mix only ever reduces the channels: a file that already has as many, or fewer, is written as it is, and files with more than 6 channels (7.1 and up) always are. When Channels is not Original, a **Downmix** style shows under it: **Standard** (the default: centre and surrounds go into left and right at -3 dB, the LFE is dropped), **Standard + bass** (the same with the LFE added at -3 dB) or **Front pair only** (left and right as they were mixed). Quad keeps front left and right and back left and right, with the centre folded into the fronts; mono is the average of the stereo mix. There is no centre boost. Changing either choice measures the loaded files again, because the loudness and the peak have to be those of the mixed sound: the Loudness, True Peak and Adjust columns show the downmixed numbers (a downmix can peak 5 dB higher than the six-channel mix, and can go over full scale before the gain comes down). Quad is not offered for ALAC, which cannot hold it (FFmpeg would make five channels with a silent centre), and choosing ALAC while Quad is chosen is refused with a reason. The choices are saved in presets and remembered between sessions. A file that cannot be mixed is written as it is, and its row does not say so yet.

**Format Presets** (the rightmost column, after Output Format, Volume and File Strategy, D-49)
Saved sets of output settings (iTunes Lossy, iTunes Lossless, CD Quality, Flac HD Multi, ALAC Multi). Pick one to fill in the format. **Save Preset** keeps your current settings under a name, and stays greyed out until you have changed something. **Delete Preset** removes the selected one.

**Volume Adjustment**
- **Target Loudness:** how loud every song should end up (mockup shows -22 LUFS). A text box with a drop-down (D-49) of common targets: -14 (Spotify, YouTube, Tidal), -16 (Apple Music, podcasts), -18, -22 (video and film editing), -23 (EBU R128) and -24 (US television). Any number can be typed; a positive number is made negative when the box is left. No up and down arrows.
- **Peak Protection:** a switch with its on/off pill to the left of the label and no box (Show Logs is the boxed button version). When on, no song is boosted so far that it distorts. The ceiling is set next to it (mockup shows -0.6 dBTP).
- **Peak key** under Peak Protection: three coloured samples explain the Adjust column. `TrackView.peak` is `kept` (green: new peak above 0 dB and the output is 32-bit float WAV), `limited` (yellow: protection held the gain back) or `clips` (red: protection off, output cannot hold a peak above 0 dB, new peak above 0.005 dB). Otherwise the cell has no colour. The `*` appears with any of the three.
- **Planned (not built):** a switch, off by default, that lets a limiter bring up to the target the songs peak protection would hold back, and says which songs it touched (D-36).

**File Strategy** (three separate choices; the mockup's single list of four has been split, decision D-21)
- **Save to** (pick one): **Next to original**; **Subfolder of original folder** (you type the name, `_forged` to begin with); or **All in one folder** (pick it with **Browse**).
- **If a file is already there** (pick one): **Add number to new file** (`_00`, `_01`, and so on), **Rename existing file** (it gets a suffix like `_old` and the new file takes its name), or **Overwrite existing file**. A name is only ever changed when it would clash, which with a CUE album is almost never.
- **Delete original after conversion:** off to begin with. It deletes a source only when every song from it was written, so an album with a song left out keeps its source.
- Overwriting and deleting both ask for a confirmation before the run starts. The question has a **Don't ask me again** box; it is only honoured when you choose **Run anyway**, and Settings has a checkbox to turn the question back on. With it off, a run that deletes originals or overwrites files starts at once.
- **All of these choices are remembered** between sessions (in `settings.json`), including the subfolder name you typed, delete and overwrite, so check them before a run if you changed them last time. The **Output Format** and **Volume Adjustment** panels are remembered the same way: the program opens with the codec, container, sample rate, bit depth, target loudness, peak protection and ceiling you left, and the matching preset (if any) is highlighted again. A box you type in (the subfolder, the suffixes, the target and ceiling) is sent when your typing pauses, not only when you leave the box, so closing the window mid-edit keeps what you typed.

**The list** (window version)
- **Song names in the rows:** a single file's row shows the name it will be written as (the single-file name pattern's result, without the extension) when that is not just its own name, so the barcode names of a vinyl download read as `Doves-Some Cities_01-Some Cities` before the run. The original file name is in the hover text, with who the song is. A name that rests on a guess from the file name and folders is in italics: typing in names (the album dialog) makes it plain. Songs cut from a CUE sheet show the name the album pattern will give them (`01 - First`), with names typed in on top of the sheet's.
- **Tick boxes** switch a song, or a whole album, in or out of the next run. Songs left out are greyed and are not counted in **Run (n)**. An album box with a dash in it has some songs in and some out.
- **Right-click** a row for the same, plus tags, names, Last.fm and **Remove from the list** (see Editing tags and names above).
- **Clear completed** and **Clear all** are under the Run button (see the controls strip).
- **Dropping an audio file** that has a CUE sheet with the same name beside it works the same as dropping the folder.
- **Dropping a folder** searches it and the folders inside it, up to four levels down, so `Artist - Album` can be dropped with `1977 - Album` and a disc's `6ch` folder inside. Each folder uses its own CUE sheets, or if it has none, its own audio files. Hidden folders, any folder named `RangeForge` (where an earlier version put its output) and the subfolder you chose in File Strategy (`_forged`, say) are skipped, so what was already written is not added again.
- **Colours** follow the system's light or dark setting. Only the first and last columns (Name and Tags) change width with the window. They share the spare width equally, and the columns between keep just the width they need.
- **Text is not selectable**, as in any program. Typing boxes and the log still are. Copying from the table will come with its right-click menu (planned).

## The Settings window

Laid out in two columns of outlined panels (D-50), up to 1040 px wide, scrolling when the window is short, one column below 900 px. Left: **File names**, then **DSD Format** (its text beside its two selects). Right: **Online lookups** (Metadata API, the Last.fm key row, a line with the key status and the link to create a key, Clear saved answers), **Hot 100 tag** (one row: switch, tag text, position) and **Before changing files**. The settings checkboxes use the plain on/off pill to the left of their text. Everything in the window waits for **Save** (D-51): the file name patterns, the DSD choices, the confirmation switch, Metadata API, Use Last.fm and the Hot 100 tag. **Cancel** (or Esc) throws the changes away. Only the key buttons (**Save key**, **Forget**, **Clear saved Last.fm answers**) act at once. While the window is open, a screen refresh does not touch its draft.

- **File names** (built, in the window version): the pattern for songs cut from a CUE album (`{track:02} - {title}` to begin with) and the pattern for single files (`{name}`). Variables go in braces: `{track}`, `{title}`, `{artist}`, `{album}`, `{albumartist}`, `{year}`, `{genre}` and `{name}` (the original file's name). `{track:02}` pads the number. Single files can use all of them too, taken from the file's own tags or, if it has none, guessed from its name and folders (see "Who a song is" below). A missing value, and the separator next to it, is left out, so a song with no track number is `Title` and not ` - Title`. A line under each box shows an example as you type and says what is wrong if the pattern is not valid. The patterns are kept in `settings.json` in the settings folder.
- **API Keys** (built): Last.fm. RangeForge ships with no key and never will (D-42): the user creates their own free one, and the window links to Last.fm's page for that. Each key field has a **Use** checkbox of its own, so a key can stay saved while switched off. Type the key and press **Save key**; **Forget** removes it. The key is stored in the computer's own credential store (Credential Manager on Windows, Keychain on macOS), never in a file and never shown again: the window only learns whether a key exists. On macOS the Keychain may ask the first time a new version reads it; choose Always Allow. (The mockup also shows a Discogs key; Discogs is parked, decision S-10.)
- **CPU:** how many processor threads the app may use. Auto, or a number you choose.
- **DSD Format** (built): DSD (`.dsf` and `.dff`) cannot be written back out as it is, so it needs a real sample rate and bit depth. The main Output Format wins wherever it names a value. This fills in only what it leaves open: **Sample Rate** (88.2 kHz to begin with) where the output says original, and **Bit Depth** (24-bit) where it says source. Each of the two is used on its own: an Output Format that names a rate but leaves the depth at source takes DSD's depth, and the other way round. Everything else (codec, container, bitrate, compression, channels and downmix) is the Output Format's own, so a DSD file is written like any other file, and a six-channel DSD file stays six channels unless Channels says otherwise. A codec that cannot write the rate (AAC above 96 kHz, MP3 above 48, Opus anything but 48) brings it down to one it can. With 32-bit float WAV chosen and the sample rate at source, the file is float WAV at DSD's sample rate. FFmpeg turns the DSD into ordinary audio, so FFmpeg has to be present (it comes inside the installers). Choices apply as soon as they are changed and are kept in `settings.json`.
- **Close.**

## The log panel

A scrolling list of short lines that each start with a dash, as in the mockup: file added, CUE found, split done, lookup results, loudness scan. It scrolls on its own and never blocks the list. (The mockup shows no timestamps.)

## When the window is resized

From the taller-window pictures:

- The list takes all the spare height.
- The controls strip keeps its size and stays glued to the bottom.
- The log panel runs the full height of the window beside both.
- Opening the log panel makes the window wider in the mockups (1440 px to 1728 px), so the list keeps its size. *Not yet decided: what happens on a window that cannot get wider.*

## The terminal version

`rangeforge ui` shows this same screen inside a terminal window, as a first working version before the desktop app. It follows the mockups where a terminal allows, and differs in a few honest ways:

- **Files come from the command line,** not drag and drop. Give it audio files, CUE sheets, or a folder.
- **Moving around:** **Tab** moves the highlight from one control to the next (Shift+Tab goes back). **Left and right** change the highlighted control: the target loudness moves by 0.5, the ceiling by 0.1, and Peak Protection, Codec, Bit Depth, Preset, Save to, If a file is already there and Delete original step through their choices. Up, Down, Page Up and Page Down scroll the table.
- **Typed fields:** the subfolder or folder, and the suffix, are edited with **e** (Enter accepts, Esc cancels). While typing, every key is just a letter, so `q` does not quit.
- **Presets:** choosing a preset fills in the codec, bit depth and volume (and the File Strategy, if the preset has one). **s** saves the current settings as a preset, but only when they differ from the selected one (or match none), as in the mockup. **d** deletes the selected preset. Presets are kept in a small file in your settings folder, and the five from the mockup are there to begin with.
- **Run:** **Enter** (or **r**) starts it. It waits if measuring is not finished and refuses if the File Strategy is not usable yet, saying why on the bottom line. Overwriting or deleting asks for a **y** first. While it runs, each album row shows `encoding 3/8` and then `saved`, and each song gets a tick when its file is written.
- **Other keys:** `p` switches peak protection, `[` and `]` move the ceiling, `l` opens the log, `q` quits.
- **Not built yet:** an optional limiter for songs peak protection holds back (D-36), Settings and tags.
- **A `*` after an Adjust value** means peak protection limited that song. It would have needed more gain to reach the target, but its true peak ran out of headroom. The controls strip explains the star.
- **A failed file** shows its message on its own line under the album.

`rangeforge ui --snapshot` prints one frame of the screen as plain text and exits, which is handy for sharing and for automated checks. Adding `--run` presses Run once measuring is done, waits for the files to be written, and prints the finished screen, going through the same checks as a real key press.

## Rules that always hold

- Nothing is written to disk until you press Run. (There is no Auto Mode: with conversions and compression in the mix, a run that starts by itself did too much at once, D-39.)
- Changing the target loudness or peak ceiling updates the **Adjust** column immediately. The app does not re-measure anything.
- Results appear file by file as each finishes.
